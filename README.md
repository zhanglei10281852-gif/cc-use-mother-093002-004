# 中文职业能力互认服务

面向在中国与东盟多地设厂的装备企业，统一合作院校中文证书与职业技能证书的
招聘互认口径。服务把**标准版本、能力单元、课程成果、实操证据与证书版本**
建立映射，支持评审组作出互认决定、走异议与复议程序，并在标准升级时计算
映射延续性与持证人补证需求；人力部门可按"申请人 + 任一历史日期"复原当时
可认可的岗位、缺失能力、待复议事项及所依据的标准版本。

## 领域规则如何落地

| 业务要求 | 实现方式 |
| --- | --- |
| 同名等级 ≠ 相同实操能力 | 证书版本显式声明依据的标准版本与逐项能力单元（`UnitClaim`），等级名称只作显示 |
| 旧证书到期补证规则一致 | 补证规则（不予补证/补交证据/重新评审）与默认有效期按**证书版本**登记 |
| 四种互认决定 | `MappingDecision`：等同、部分等同、附加考核、不予互认，并有严格口径校验（等同必须全覆盖等） |
| 异议、利益冲突回避、复议过程留痕 | `ReviewCase` 状态机 + 评审人隶属关系冲突检测 + 主动回避申报 + 异议受理/驳回 + 复议维持/改判，全部操作进事件流 |
| 同一证据不能重复提交绕过有效期/次数 | `EvidenceLedger`：有效期 + 最大使用次数 + 提交令牌幂等；换案件、换令牌也不能超额使用 |
| 并行评审不能覆盖已生效结论 | 案件乐观锁 `expected_version`；已生效结论只能经复议替代，旧映射在历史区间内原样保留 |
| 标准升级不能改写历史依据 | 标准版本对象不可变，只追加"废止事实"；映射按生效区间解释，`is_effective_on(历史日)` 永远成立 |
| 升级时计算映射与持证人影响 | `apply_standard_upgrade` 逐映射判定"继续有效/需复议"（新增、删除、语义变化），列出需补证持证人与锚定旧版的岗位 |
| 历史时点查询 | `recognize(申请人, 日期)` 为纯函数：只读取不晚于该日的事实，分别复原可认可岗位、缺失能力、待复议事项、依据的标准版本与映射 |

## 模块结构（`src/skill_recognition/`）

- `standards.py` — 标准版本、能力单元、前驱谱系与废止登记（旧版不可变）
- `certificates.py` — 院校证书版本、等级口径、补证规则、持证登记簿
- `evidence.py` — 实操证据登记与使用台账（有效期/次数/令牌幂等）
- `mappings.py` — 互认映射、四种决定与口径校验、失效替代
- `review.py` — 评审组、回避、异议、复议、案件乐观并发控制
- `positions.py` — 锚定标准版本与等级的企业岗位目录
- `engine.py` — 任一历史日期认可状态的纯函数复原
- `service.py` — 用例门面：结论落映射、升级影响分析、延续/送复议、历史查询
- `errors.py` — 领域错误（校验、冲突、并发、过期、次数耗尽等）

关键的口径隔离：互认映射依据按 **(标准版本, 目标等级, 能力单元)** 归集，
"中级证→中级"的等同不能用于满足"高级"岗；实操证据按 **(标准版本, 单元)**
直接证明，与等级无关。

## 运行

```bash
python3 -m unittest discover -s tests -v     # 58 个领域测试
python3 -m compileall -q src tests run_cli.py
python3 run_cli.py                           # 端到端冒烟演示
```

冒烟演示覆盖：冲突评审人拦截 → 证据一次性使用与令牌重放拦截 → 附加考核落
映射 → 岗位认可 → 证据过期后缺口重现 → 标准 2022 版升级影响计算 →
历史查询仍依据旧标准版本。
